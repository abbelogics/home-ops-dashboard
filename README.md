# Home Ops Dashboard

A desk display that knows what's going on at home: the planes flying past the
window, the real weather outside (not a forecast guess), the next calendar
event, what's playing, whether the homelab is healthy - on an
**ESP32-S3-BOX-3** touchscreen driven by an **n8n** backend on a Raspberry Pi.

Built as a human + AI pair: every screen, workflow and bug fix came out of
working sessions between the owner and [Claude Code](https://claude.com/claude-code)
(Anthropic). See [How it was built](#how-it-was-built).

| | |
|---|---|

| Backend workflows (n8n) | **11** active, 108 nodes, from every 2 s to hourly |
| Aircraft sightings logged | **4,600+** in the first 12 days (see [ADS-B radar](https://github.com/abbelogics/adsb-radar)) |
| Weather sources fused | **3** (radar, airport observation, model) + official alerts |

## Screens

| Screen | What it shows |
|---|---|
| **Home** | Clock, date, room temperature/humidity (on-board sensor), outside weather, a one-line **imminent-weather** warning (only when something's about to happen), and a notification bar (calendar, now playing, F1 sessions, alerts). When a plane is in view it takes over: airline logo, flight, route, altitude, distance, where to look - with a chime and gold frame for 747s, A380s and military |
| **Weather** | Now, feels-like, high/low, UV, gusts, a radar line ("Dry here · rain 4.2 mi away"), and a 3-day forecast |
| **Systems** | Health of the homelab machines (receiver Pi, VPN Pi, NAS, main Pi) |
| **Lights** | Philips Hue control, including voice commands on the device's microphone |
| **FlightAware** | Route-lookup API usage for the aircraft pipeline |
| **2FA** | An on-device TOTP authenticator code |
| **Claude / OpenAI usage** | Session and weekly usage of the AI tools used to build all this |
| **FX** | USD against COP, EUR and GBP from the official sources |
| **Spotify** | Transport controls and volume for the living-room speaker |
| **Notifications** | History of alerts you missed, each dismissible |

## Architecture

```
  ESP32-S3-BOX-3  (ESP-IDF, LVGL, MQTT client)
        ▲  retained MQTT topics: aircraft, weather, systems, lights,
        │  notification, spotify, fx, usage, f1 ...
        │
  Mosquitto  ◄───  n8n on a Raspberry Pi 5 (Docker)
                     Aircraft Poll ........ every 2 s
                     Spotify Now Playing .. every 5 s
                     Health / Calendar / Lights .. every 30 s
                     F1 Sessions .......... every minute
                     NWS Alerts ........... every 2 min
                     Weather Poll ......... every 5 min + instant webhook
                     MIA flight board ..... every 10 min
                     FX ................... hourly
                     Error Handler ........ one alert per incident
        │
        ├── PostgreSQL: state cache, aircraft + weather history
        ├── wx-nowcast service: NOAA MRMS radar at the house's 1 km cell
        └── external: ADS-B receiver, Open-Meteo, aviation METAR, NWS,
            Hue, Spotify, Google Calendar, FlightAware, FX sources
```

Every n8n workflow is **generated by a Python script** (`n8n/rebuild_*.py`)
and pushed through the n8n REST API - the scripts are the source of truth,
so every behavior change is versioned and reviewable.

## Highlights

- **Weather that matches the window.** Rain comes from NOAA's MRMS radar at
  the house's own 1 km cell (checked every 20 s, ~3 min behind reality -
  NOAA's own processing floor), sky cover from the nearest airport's METAR
  observation, temperatures and forecast from a model. A rain-state change
  pushes an update to the display within seconds.
- **Official alerts for the exact point** (hurricanes, flood and coastal
  flood advisories, severe storms) on the notification bar and Telegram,
  deduplicated so an updated alert doesn't re-page.
- **Aircraft with context**: line-of-sight filtering, route lookups that use
  free sources first, a callsign fill-in for planes first heard without one,
  special-aircraft chime.
- **Quiet by design**: the home screen only adds a warning line when
  something is imminent; alerts are throttled to one per incident; UI changes
  were chosen from to-scale mockups before flashing.

## Repository layout

| Path | What |
|---|---|
| `firmware/box3/main/` | Device firmware: screens, MQTT handlers, sound, sensors, voice |
| `firmware/box3/tools/` | Scripts that compile PNG icons/logos into C image descriptors |
| `n8n/` | One script per workflow; each builds the workflow JSON and PUTs it to n8n |
| `pilab-scripts/wx_nowcast.py` | Radar nowcast service (NOAA MRMS GRIB2 decoding) |
| `docs/BUILD_NOTES.md` | Real problems found and how they were fixed |

**Not included:** airline logos (airline trademarks) and icon image assets
(third-party licenses; the weather icons are derived from
[Twemoji](https://github.com/jdecked/twemoji), CC-BY 4.0) - the `tools/`
scripts regenerate the C files from your own PNGs. Hosts, IDs, chat IDs,
location and secrets are placeholders; secrets are never in the repo (see
`firmware/box3/main/Kconfig.projbuild` and the gitignored `sdkconfig.local`).

## How it was built

Designed, built and debugged with Claude Code, over many short sessions:

- **Measure, don't guess** - problems were traced through live data: n8n
  execution history, the database, the MQTT broker log, LVGL's own snapshot
  API.
- **Mockups before firmware** - layouts were rendered to scale with the real
  font and icons and chosen by the owner before a flash.
- **Everything as code** - firmware in git, workflows generated by scripts,
  a living project log.
- **Privacy by construction** - this public copy is generated from the
  private repo by an export script that fails if a name, address, private IP,
  ID or live secret would be published.
